# Multiseat desktop launch handoff, 2026-10-10

Deployed tracked desktop/game launch jobs, responsive desktop-only polling, restart recovery, and a bounded Apollo PIN acceptance wait. Verified the production friend flow with a disposable account and real Windows rendering.

## Changes

- Portal desktop/game launch uses an authenticated 202 job acknowledgement and polls progress, avoiding the former long synchronous request timeout. Existing synchronous API clients remain supported.
- Duplicate running launches for one owner/host share the same job. Different operations and stopping during launch return 409. Job status is scoped to the signed-in realm and username.
- Persisted jobs identify their worker by PID and process birth time. Interrupted workers produce a retryable failure; live workers are retained, including after another worker handles a status request.
- Desktop-only portal and game-library polling skips global VM inventory. Legacy VM assignments and VM-granted accounts still use inventory and migration.
- Consecutive Moonlight route checks reuse a one-second Docker inventory, including stopped-container collision checks, and invalidate it before staging.
- The host publisher uses the private SSH route and checks every five seconds. Slow gaming VM frame checks run separately without blocking seat publishing.
- The Windows agent error handler now preserves structured provider errors. Multiseat PIN submission waits up to twenty seconds through explicit Apollo pending rejections, matching the existing Sunshine path. Ambiguous transport errors are not automatically retried.

Subsequent canvas sampling contained 159 color levels, and the exported full rendered frame in handoff-reload-rendered-frame.png was inspected and showed Windows again. Full-page screenshot capture timed out once; rendering was verified independently from the canvas.

## Pairing evidence and limits

Earlier attempts on the existing QA seat exposed an immediate PIN rejection and later incomplete handshakes. After installing the bounded PIN wait and recreating only the disposable QA seat, the fresh launch and resume succeeded. The exact cause of the later incomplete handshakes on the earlier seat was not established. This is a controlled flow check, not a long soak test or proof that every pairing failure recovers automatically.

First setup can still take around two minutes. No startup-speed claim is made from the 148-second trace versus the 116-second browser handoff because the seat state and measurement boundaries differ. The Windows privacy setup is intentionally retained as requested. Physical controller input, rumble, game compatibility, and a prolonged network outage were not retested.
